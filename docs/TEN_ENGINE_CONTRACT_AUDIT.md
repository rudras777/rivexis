## Cross-engine contract rules

For newly executed live runs, the dispatcher enforces a canonical current engine version for each engine. Evidence inherits the parent engine contract version while preserving a more specific calculation version when needed. Historical persisted analyses are not rewritten.

Provider consensus is derived from evidence actually present. Zero provider evidence cannot claim `SINGLE_SOURCE`; one provider is `SINGLE_SOURCE`; multiple providers are `MULTI_SOURCE`; unresolved conflicts are `CONFLICTING`. `USER_INPUT_ONLY` is preserved only for intentionally modeled results without provider evidence.

Unresolved provider conflicts are first-class analysis state. Fresh live results carrying unresolved source conflicts are promoted from ordinary completed/partial states to `CONFLICTING_DATA`; stale and terminal unavailable states remain stronger gates where applicable.

## Engine-specific trust-boundary notes

**B1.** Standard ERC-20/ERC-721/ERC-1155 effects come only from raw logs whose standard topic signature and ABI layout validate. Receipt logs for mined transactions are observed evidence; Tenderly simulation logs are predicted. Non-canonical calldata, trace and state-diff records remain malformed rather than coerced. Validated evidence can emit bounded structural review cues for delegate/callcode execution context, creation/self-destruct paths, internal failures, broad approval candidates, account lifecycle and code changes. These cues do not change the risk score and are explicitly not maliciousness or safety verdicts; protocol/asset identity remains unknown without independent evidence. Tuple arrays, nested tuples, dynamic tuple members and other nested composites are not guessed.

**B2.** Input and RPC-resolved addresses/hashes validate before downstream use. Block quantities must be canonical uint256 JSON-RPC quantities. Contract code must be valid, capped at 128 KiB and observed at the captured block; evidence includes its byte length and Keccak-256 hash. The push-aware parser skips PUSH data before reporting structural opcode presence, while only the exact EIP-1167 runtime shape yields an embedded implementation address. These observations are review context—not reachability, exploitability, vulnerability or safety conclusions. Etherscan source/proxy metadata must have one canonical result and a valid implementation/proxy relationship; it never inherits the RPC block and remains UNKNOWN-fresh without its own observation time. A direct/explorer implementation mismatch clears resolved identity, records a high-severity unresolved `SourceConflict`, and dispatches as `CONFLICTING_DATA`. Approval-shaped calldata follows the same canonical address/bool boundary as B1.

**B3.** Current and prior snapshots are trust boundaries. All direct state forming a current snapshot—balance, bounded code, optional supply and supplied Chainlink state—shares the captured block tag. JSON-RPC quantities must use canonical uint256 encoding; `totalSupply()` and Chainlink `decimals()` require exact 32-byte ABI words. Snapshot change detection requires a dependency-identified prior snapshot with a valid block number strictly below the current block; malformed or non-monotonic prior state cannot manufacture deltas. Empty/malformed Blockaid payloads are unavailable. Valid screening without a provider observation timestamp/block is retained with `block_number=None` and UNKNOWN freshness; aggregate freshness becomes UNKNOWN while direct state remains separately LIVE.

**B4.** Direct-chain and external-provider provenance is explicitly separated. The captured RPC block applies only to the direct native-balance snapshot, and its quantities require canonical bounded JSON-RPC encoding. Etherscan history pages and Nansen/Arkham label responses without a provider-normalized observation timestamp or block are stored with `block_number=None` and `FreshnessStatus.UNKNOWN`; retrieval time is not converted into provider observation time. Non-object indexer rows are counted as malformed instead of disappearing. A self-transfer is retained as activity but contributes neither inbound nor outbound value and never makes the monitored wallet its own counterparty. B4 aggregate freshness remains UNKNOWN whenever external evidence is consumed, while `direct_state=LIVE` preserves the current chain snapshot. Counterparty concentration remains descriptive interaction concentration—not ownership, maliciousness or economic exposure.

**B5.** Caller request plus LI.FI response form one trust boundary. Route/tool identity and output/minimum amounts are required; amounts are bounded to uint256. Optional approval metadata must be a canonical EVM address. Gas/fee collections and included steps are bounded, every step has a unique bounded ID, and duration/slippage must be valid non-boolean numerics. LI.FI retrieval time is not treated as a provider observation timestamp, so aggregate quote freshness remains UNKNOWN. Contradictions retain evidence but discard route scoring.

**F1.** Explicit wallet/token reads are all-or-nothing. All direct holdings reads in one live snapshot share the captured block tag. For every declared ERC-20 contract, Rivexis first reads `decimals()` at that block and requires one canonical 32-byte ABI uint256 word; `balanceOf(address)` is held to the same ABI-width rule. Caller-supplied decimals must equal the observed on-chain decimals before any raw balance is scaled. Malformed, over-range or contradictory direct state prevents scoring instead of becoming zero or a plausible quantity. Direct JSON-RPC block/native quantities are bounded to uint256. Positive exposures still require complete positive finite prices before weights/concentration scoring, and market freshness requires credible timestamp coverage. Contract address, symbol and CoinGecko ID remain caller-supplied mapping metadata until independent discovery/identity evidence exists. Ordinary provider errors preserve the global redaction boundary rather than exposing raw internal mismatch details.

**F2.** Provider numerics reject Python/JSON booleans before float coercion. Boolean TVL in history, top-level TVL or `currentChainTvls` is malformed evidence; boolean timestamps cannot establish observation time. Audit counts/links cannot gain scoring trust through boolean truthiness, insecure references, contradictions or declaration-only claims. Optional protocol-native reads now pin all contract/proxy/oracle calls to the captured canonical block. Runtime code is canonical hex and capped at 128 KiB; EIP-1967 and oracle returns require exact ABI words. Malformed direct/explorer identity is unavailable rather than plausible state. Explorer metadata remains blockless/UNKNOWN without its own observation time, future oracle timestamps remain UNKNOWN, and F2 aggregate freshness is the conservative state across retained evidence.

**F3.** Explicit protocol-adapter requests remain authoritative when a position is returned. Generic modeled inputs reject booleans and non-finite values. Chainlink responses require exact five-word layout and positive finite prices, with both feed calls pinned to the captured block. Materially future or unusable timestamps remain UNKNOWN. CoinGecko reference freshness is based on its own usable observation timestamp rather than retrieval-time optimism.

**F4.** Strategy identity must be bounded and resolve uniquely through exact or delimiter-aware matching; arbitrary substring matches cannot select a pool. Provider collections and selected identity fields are capped before evidence construction. Core and present optional yield/volatility values reject booleans, non-finite values and impossible semantics; reward APY above headline APY is contradictory rather than clamped. Missing or materially future provider timestamps remain UNKNOWN rather than inheriting retrieval time. Native-state confidence is available only when native evidence exists, and aggregate freshness conservatively includes every retained pool, native and explorer observation.

**F5.** Treasury numbers reject booleans before float coercion. Every requested CoinGecko asset must carry a usable observation timestamp before Rivexis asserts freshness; the oldest valid timestamp bounds aggregate freshness.

## External gates that remain non-code blockers

- Arkham remains license/terms-gated.
- Hypernative native screening remains customer-schema/contract gated where the exact authenticated request contract is not public/approved.
- Tenderly, Blockaid, Nansen, explorer and RPC behavior depends on deployment configuration and valid credentials/entitlements.
- Absence of those integrations must remain explicit provider-unavailable/partial/UNKNOWN-compatible evidence, not synthetic success.
