# Dependency-security follow-up — 3 November 2026

The production PR125 lock initially reported three moderate npm entries originating from [Satori SVG escaping](https://github.com/advisories/GHSA-wx4j-mvgx-mqwp). Application source has no dynamic `ImageResponse`, Satori or Open Graph generation route. No exploitation or customer-data exposure is inferred.

The candidate pins Vinext 1.0.0, the first stable release whose published peer ranges accept the existing React 19.3.0 and RSC plugin 0.5.35. Its renderer dependency is exactly `@vercel/og` 1.0.3 / Satori 0.33.5. Newer Vinext releases examined require newer peers and were not selected. Existing Next, React, Vite, Wrangler, sharp, financial modules and production identifiers are preserved.

Satori's declared compression dependency initially resolved to fflate 0.7.3, affected by [malformed ZIP64 handling](https://github.com/advisories/GHSA-px8p-9vwx-vf98). The root override retains patched fflate 0.7.5. This npm installation preserved stale override records during ordinary lock-only updates. A clean, manifest-only disposable resolver produced the correct 0.7.5 registry/integrity record. Only that resolver-produced leaf record was adopted; unrelated freshly resolved packages and platform-runtime reshuffling were rejected. The existing lock's other security pins remain unchanged.

Actual `npm ci` installed the intended versions and the subsequent full audit reported zero findings. This is a registry-advisory result, not proof of absence of vulnerabilities. Direct Satori SVG rendering passed. A separate direct Node ESM `ImageResponse` probe failed in bundled HarfBuzz with unsupported dynamic `fs` require. That unused Node rendering path is not certified; do not introduce it as a product feature without resolving and testing it. The current application's Worker build/static document and dry-run passed; full CI/browser/release verification remains necessary before promotion.

Validation also reproduced stale incremental TypeScript diagnostics claiming that generated route exports were missing. Regenerating types and rebuilding alone retained the error; a nonincremental resolution trace resolved the same route file and passed. `typecheck` now runs the installed Next CLI's documented `next typegen` and a fresh `tsc --noEmit --incremental false`. The custom Vinext augmentation lives in owned `types/vinext.d.ts`; generated `next-env.d.ts` is retained locally and ignored by Git, rather than hand-edited. CI rechecks types after the Worker build. No type assertions, compiler strictness, security checks or financial tests were weakened.
