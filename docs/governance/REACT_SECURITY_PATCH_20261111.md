# React RSC security patch — 11 November 2026

**Implemented; protected release and live acceptance pending.** The existing npm security gate blocked the initial PR137 web job at the newly observed critical `react-server-dom-webpack` finding. [React's advisory GHSA-xqc2-xf4c-x3h3](https://github.com/react/react/security/advisories/GHSA-xqc2-xf4c-x3h3) lists19.3.0 as affected and19.3.1 as patched; its metadata was updated10 November. [Official release](https://github.com/react/react/releases/tag/v19.3.1). This is a dependency finding, not evidence that RIVEXIS was compromised or that a production exploit was reproduced.

The web workspace pins React, React DOM and react-server-dom-webpack to19.3.1 together. The RSC package's published peer requirements are React/DOM `^19.3.1`; Vinext1.0.0's ranges accept them. The installed graph resolves one deduplicated19.3.1 copy per package for the web workspace, Vinext and its RSC plugin. The lockfile changes exactly these three installed package versions plus their workspace declarations; existing security overrides and all other package versions remain unchanged. Next16.4.2, Vite8.3.5, Vinext1.0.0 and RSC plugin0.5.35 are preserved.

Local npm audit now reports zero known findings at every severity; the existing severity gate passes without exceptions, suppressed advisories or audit-level changes. Types/lint pass. These are current registry and source results, not a universal vulnerability guarantee. The original blocked CI run42978396585 remains failure evidence; only checks for the corrected head may qualify release. Cross-browser compatibility is required for this runtime patch, alongside the existing six protected gates, same-Worker deployment, exact commit readback and both-host live acceptance. A live safe payload test is not an RCE exploit test; no attack payload was submitted to production.

No UI redesign, branding, financial calculation, authentication policy, database data, DNS, credentials or plan change is included. The ordinary previous-Worker rollback remains available, but returning to a known affected dependency version is a security regression requiring incident judgment.
