# Interface refinement — 20-21 November 2026

Implemented on `feature/control-refinement`; not merged or deployed. The owner requested Hypurrscan-like button layout and smoothness, plus removal of unnecessary wording and lines. This is a presentation change on top of frontend release `f1da438a`; inactive API44 and the database/worker/email activation holds are unaffected.

## Design and scope

The public [Hypurrscan dashboard](https://hypurrscan.io/dashboard) was inspected through the bundled Browser. Its compact action groups and restrained transitions informed the first candidate. On 21 November the owner rejected the remaining boxed presentation and heavy typography; the current revision uses open sections and text-led actions. No reference-site code, assets, market data or branding is copied into Rivexis.

`apps/web/app/controls.css` defines shared 40px desktop / 44px mobile hit areas and restrained 160ms transitions. `editorial.css`, imported last, removes decorative card frames, fills and shadows across public, workspace, account and chart surfaces. Headings use the existing variable Geist font at 300-350 weight; controls use 400. Primary actions use an underline, fields one baseline, and tabs an active underline. Open metrics and sections rely on spacing rather than cards. Keyboard focus, reduced motion, larger text and forced colors remain supported. Theme colors, logo, typeface, destinations, request handling and financial calculations remain intact. Table/plot lines retain their meaning; menu/dialog/tooltip overlays retain opaque backgrounds for legibility. Decorative background cubes are hidden.

Coverage, address and wallet inspection now share a row on desktop; secondary actions sit beneath. Mobile stacks the inputs and keeps actions usable. Public/workspace navigation, settings and analysis tabs use the same underline selection vocabulary. Workspace category labels are shorter while their descriptive accessible names and destinations remain unchanged. The redundant sticky workspace strip separator and repeated decorative labels are removed. No new interaction library or runtime state machine is introduced; the decorative cursor listener is removed.

Landing, product, account-entry and financial-workspace copy is shorter. Repeated slogans and explanatory filler are removed. Financial source/coverage labels, hypothetical-data labels, unavailable/stale states, consent/permission messages, calculation assumptions and execution limitations remain explicit. Existing copy-dependent test assertions are updated without weakening their behavior checks.

## Verification and rollout

Run the existing frontend AST check, type check, production build and browser suites. Verify the actual compiled CSS, desktop/mobile geometry, both themes, grouped-menu click/Escape behavior, settings keyboard tabs, sample workflow, disabled/loading controls and reduced motion using synthetic local fixtures. Preview blocks production API forwarding and contains no production accounts or records. Record exact-head CI and screenshots in the implementation PR/delivery evidence; earlier release results do not certify this candidate.

Local AST/type checks and a production build passed during implementation. An intermediate build rejected a dangling selector left during removal of cursor CSS; that selector was corrected, and the next build passed. The final source/CI and visual results are recorded in the PR. No new tests are added solely to mirror CSS declarations. The intentional light wallet-form background assertion now expects transparency; contrast and hover accessibility checks remain unchanged. The background test now requires all decorative cubes to be hidden instead of measuring their visible faces, retaining every no-financial-request, legacy-graphics, geometry and motion check. The first exact-head Chromium CI run passed 361 cases and failed that superseded cube-size assertion; the failure remains recorded in delivery evidence. Historical 20 November results cover the preceding candidate only. Fresh 21 November verification belongs to the open-layout revision. The initial local Playwright launch was unavailable because its pinned browser binary was absent; no application test ran in that attempt. The pinned official browser was then installed for existing tests.

Existing axe checks caught a light selected-label contrast regression, and the market-view checks caught lost sticky workspace context; both are corrected with their original assertions retained. The primary-hover accessibility check remains in place for the current transparent, theme-aware action style; the darker filled hover belongs only to the superseded 20 November candidate. Firefox also exposed a health-fixture navigation stall: the document was complete with HTTP200, but the driver's DOMContentLoaded wait outlasted an intentionally held health reply. Those clock-driven fixtures now require one HTTP200 document commit and retain all hydration/response/counter/banner/deadline checks. They do not reload the page or loosen the navigation guard.
