## Defect repaired

The current-browser logout handler previously ignored errors from Supabase `setSession` and `signOut`, then always returned `status: revoked`. A provider failure could therefore produce a false revocation claim. The handler now always clears the local HttpOnly cookie and separately reports whether refresh-session revocation was confirmed. Establishment/sign-out errors and exceptions return `browser_session_cleared` with `refreshSessionRevoked: false`. Successful revocation preserves `revoked`; both responses disclose that previously issued access tokens may remain valid until expiry.

AppShell clears account preferences, workspace caches, wallet access and financial state in both cases. An unconfirmed provider revocation shows only a session shell explaining the limited result, with login/public-site links. A transport failure before a server response retains the existing retry behavior because cookie clearing cannot be confirmed. Login, signup, recovery, logo, navigation and design were preserved.

## Fresh read-only production database/security observations

- All **61 public ordinary tables** have RLS enabled; none lack RLS. RLS was inspected through catalog queries, not inferred only from migration files.
- All **13 inspected Rivexis privileged/legacy public functions** deny EXECUTE to both `anon` and `authenticated`. SECURITY DEFINER helpers have explicit search paths. Beta quota/save-report functions are SECURITY INVOKER and also deny public client execution.
- `users`, `profiles`, `workspaces`, `organization_members`, `rivexis_defi_budget` and `rivexis_defi_reports` deny SELECT to both client roles. Edge server actors provide the supported access path.
- Advisor:19 RLS-with-no-policy INFO findings are intentional deny-by-default legacy/internal tables, including server-only beta reports/budget. Adding client policies to silence these notices would widen access and was not done.
- Advisor WARN remains: `pg_net` extension in public schema. [Supabase remediation](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public). Moving an installed extension requires a controlled dependency review; no high-risk migration attempted.
- Advisor WARN remains: leaked-password protection disabled. [Supabase password security guidance](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). No plan upgrade or account-security setting change attempted. This is a launch-hardening gap, not proof of compromised credentials.
- Actual PostgreSQL version: **17.6**. The [2026-09-25 Supabase minor-update notice](https://supabase.com/changelog/postgres-15-19-17-11-breaking-changes) describes security fixes in15.19/17.11 and extension/index upgrade considerations. A controlled supported minor-upgrade review is required before claiming the database is current. Installed relevant extensions include pgcrypto1.3; no ltree/btree_gist observed. No server upgrade was attempted.
- Performance advisor:104 unused-index INFO findings. A bounded-beta workload is insufficient evidence to delete indexes; no indexes were dropped.
- Reviewed current [Supabase changelog](https://supabase.com/changelog) and [Data API security guidance](https://supabase.com/docs/guides/api/securing-your-api). No applicable SDK migration was needed for this scoped fix.
